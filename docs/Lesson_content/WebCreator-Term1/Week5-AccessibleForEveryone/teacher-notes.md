# Teacher Notes — Week 5: A Website for Everyone

## Outcomes

Learners navigate by keyboard, identify visible focus, use logical headings and real controls, and explain why accessibility requires human feedback as well as automated checks.

## Suggested flow

1. Ask everyone to put the mouse aside and reach the button with Tab and Enter.
2. Demonstrate a deliberately invisible focus style, then restore `:focus-visible`.
3. Read one complicated sentence aloud and collaboratively simplify it.
4. Run the five-point accessibility check in pairs.

## Language

Avoid presenting disability as a problem that technology “fixes.” The barriers are often created by design decisions. Use examples that also show broad benefits: captions help in noisy rooms; clear focus helps keyboard users and people with temporary injuries.

## Differentiation

Younger learners can use a printed checklist. Older learners should explain the focus movement in the JavaScript and identify the limitations of an AI-only audit.
