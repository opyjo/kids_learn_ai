# Term 2, Lesson 9: Showcase + Python Beginner Badge! 🎉

## Teacher's Guide

**Duration:** 60 minutes | **Week:** 9 of 9

## Purpose

Celebrate completed projects while making student thinking visible. The showcase rewards planning, testing, debugging, feedback, revision, and explanation—not only decorative output or a program that happens to run once.

## Outcomes

Every student should:

1. demonstrate a valid calculator test;
2. explain one design choice;
3. describe one test and its expected result;
4. name one improvement made after feedback;
5. state the division-by-zero limitation honestly;
6. give constructive audience feedback; and
7. reflect on their growth before receiving the badge.

## Preparation

- Confirm every student can access their Trinket.
- Arrange a presentation order and a visible timer.
- Prepare audience feedback cards: “One strength…” and “One question…”
- Prepare the Python Beginner badges.
- Have a backup screenshot or copied code for students with connection trouble.

## Lesson Flow

| Time | Activity |
| --- | --- |
| 0–7 min | Welcome, expectations, and final evidence check |
| 7–37 min | 60–90 second student presentations |
| 37–47 min | Gallery tests or paired calculator exchange |
| 47–53 min | Term skills reflection |
| 53–58 min | Badge ceremony |
| 58–60 min | Term 3 preview and close |

Adjust presentation time for class size, but protect the reflection and badge ceremony.

## Presentation Protocol

Prompt each presenter to cover:

- “My calculator…”
- “I chose `float()` because…”
- “One test I ran was…”
- “The expected result was…”
- “After feedback, I improved…”
- “One current limitation is…”

If a program fails during the presentation, treat it as a debugging opportunity, not a failed showcase. Ask the student to explain their expected result and the evidence they collected previously.

## Audience Protocol

Audience members should not rank projects. They record:

- one specific strength;
- one respectful question; and
- one result they verified by hand during the gallery test.

## Badge Evidence

Award the badge for demonstrated growth across the term. Look for evidence in these categories:

| Category | Evidence |
| --- | --- |
| Maths | Correct use of operators and result variables |
| Data | Appropriate `int()`/`float()` conversion |
| Communication | Labels, units, rounding, and formatting |
| Testing | Predicted and actual results recorded |
| Debugging | A described symptom, repair, or improvement |
| Collaboration | Peer feedback given and used respectfully |
| Explanation | Student can explain code they submitted |

## Reflection Prompts

- Which prediction surprised you?
- Which test exposed a bug?
- How did peer feedback change your work?
- When would you choose `int()` instead of `float()`?
- Why is a calculator result different from an AI prediction?
- What limitation could Term 3 decisions help you solve?

## Term 3 Bridge

Explain that `if/else` will let calculators react to conditions such as a zero divisor or a selected operation. Do not teach the syntax during the celebration; use it as motivation for the next term.

## Family Follow-Up

Encourage students to demonstrate one test at home and explain the collect–convert–calculate–communicate pipeline. Families should ask how the student verified the result rather than focusing only on visual decoration.
