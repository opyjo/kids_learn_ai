# Term 2, Lesson 6: Math Problem-Solving Lab! 🛠️

## Teacher's Guide

**Duration:** 60 minutes | **Week:** 6 of 9

## Purpose

This is an application studio, not another teacher-led calculator lesson. Students choose one bounded problem, plan the data pipeline and tests, build a minimal tool, watch a peer use it, and revise it.

## Objectives

Students can define a problem, select types, express a formula in words, plan expected tests, construct a pipeline independently, and revise from evidence.

## Lesson Flow

| Time | Activity |
| --- | --- |
| 0–8 min | Introduce three tool briefs and choose |
| 8–17 min | Complete design card and conference |
| 17–22 min | Write expected test cases |
| 22–40 min | Build smallest working version |
| 40–48 min | Run and record tests |
| 48–55 min | Partner usability test and revision |
| 55–60 min | 60-second reasoning demos |

## Facilitation Rules

- Approve the problem and formula before coding.
- Offer patterns and questions, not full solutions.
- Keep each tool single-purpose.
- Remove or redirect menus and `if/else`; Term 3 owns decisions.
- Require `float()` for decimal-capable money or distance values and `int()` for counts.
- Require expected answers before testing.
- Ask students to name a known limitation rather than prematurely add error handling.

## Tool Brief Boundaries

**Journey:** one conversion direction only; decimal input; rounded result.

**Team Score:** three whole-number inputs; total and rounded average.

**Party Share:** whole-number inputs; `//` and `%`; no division-by-zero case.

## Differentiation

**Support:** Assign a brief, provide a partially completed design card, and reduce the first version to one input and one fixed conversion factor.

**Extension:** Add one connected output or a stronger test. More code is only valuable when it improves the same job.

## Assessment

Use the design card, working pipeline, test table, peer feedback, revision, and demo explanation as the evidence. Visual decoration is not evidence of mathematical understanding.

## Homework Boundary

Students improve Version 1. They do not start a separate calculator or copy a generic four-operation program.

## Looking Ahead

Lesson 7 formalizes debugging and verification before the capstone build.
